# 治具上方徘徊：离线 A/B 评估与后续处理

本次已完成两版模型的离线采样，不连接机器人、不重训、不修改采集数据或部署参数。新增工具及结果位于 force-VLA，原 Evo-RLT 和环境未修改。

## 先回答数据与架构问题

### 80.6% 的保持窗口是否需要重采

不需要据此全部重采。这个数字仅表示：在指定高度范围内，RB 窗口第 20 步目标 Z 与当前 Z 的差不超过 5 mm。它没有检查 XY、旋转、夹爪、接触保持或力矩变化，不能作为删除标准。

建议先在现有轨迹上做标注和采样调整：

- 同时检查位置、旋转、夹爪、力矩变化和视频，区分操作员等待、微调、接触保持、压紧和完成后的停留。
- 对无操作等待降低采样权重；保留持续压紧、接触判断、微调与动作切换边界。
- 补标正确下压与就位段，确认这些段数量和覆盖范围后，再决定补采缺少的姿态或接触情况。
- 保留原始时间轴。不能删除中间帧后把两段拼接，否则过去 2 秒历史和未来 50 步的时序关系会失真。
- 重新构建采样索引或损失掩码后需要再训练；仅改标签文件不会改变已保存模型。

本轮还核对了原始训练分布：

| 统计 | 旧 aligned 30k | v3 30k |
| --- | ---: | ---: |
| 原始训练轨迹中的 RB 窗口占比 | 7.75% | 44.22% |
| 训练采样器指定的 RB 占比 | 25% | 25% |
| 高度 0.28–0.34 m 中原始 Z 保持占比 | 72.56% | 72.14% |
| 按实际采样权重计算的该区域 Z 保持占比 | 73.09% | 68.23% |

因此，不能把新版问题直接归因为“静止样本明显增多”或“RB 被过度加权”。25% 在旧数据上增加 RB 权重，在新版上却降低其权重。RB 也不是“正确下压”标签。

### 推理是否读取外部关节力矩、末端六维力

有读取，但当前网络没有使用：

- `src/collection_31d/robot_31d.py` 从同次 libfranka 状态读取 `tau_J`、`tau_ext_hat_filtered`、`dq`。
- 父级快照包含 `base_wrench`，来自 `O_F_ext_hat_K`，属于模型估计的末端六维外力，并非额外安装的六维力传感器实测值。
- 父级快照与 31D 适配器的状态读取是先后发生的；图像使用主机时间戳和新鲜度检查，不能表述为所有传感器严格硬件同步。
- `realtime_control.py` 只向 `TorqueHistory` 加入 `snapshot.joint_torques`；模型只收到 10×7 的 `tau_J` 历史。
- 当前控制 JSONL 记录 measured/predicted `tau_J`，没有将另两种外力建立相同的历史输入。
- 31D 数据已经保存 7D 外部关节力矩，可以重用；31D 向量本身不含末端六维力。

`use_external_torque=true` 当前会被配置校验拒绝。接入外部力矩需同时改数据加载、训练归一化、适配器维度、部署历史及 checkpoint 配置，再训练验证。不能只在推理时塞入新字段。

### 是否需要解冻视觉编码器

暂不作为第一步。当前冻结视觉编码器，但语言模型和动作专家有 LoRA，力矩适配器及相关投影层也在训练。冻结视觉并不等于完全不使用视觉。

若阶段标注、数据混合与采样优化后，模型仍无法区分人工可见的微小对准差异，再做“冻结 / 视觉末层可训练或视觉 LoRA”的对照。全量解冻会增加显存需求和小数据过拟合风险。

只改 `freeze_vision_encoder=false` 不够：`training.configure_trainable()` 会先冻结全部参数，再按白名单开放训练；当前白名单不包含视觉参数，需要同时调整优化器的参数集合并验证梯度。

### 是否采到了纠偏过程

轨迹和视频可以包含这些真实动作；当前缺少的是对应的细分语义标签。现有记录只有整条成功/失败、一个连续 RB 关键区间，且 RB 不作为模型输入或阶段分类监督。

建议在已有视频中标注区间：接近、错误接触、有效纠偏、对准下压、就位压紧、释放回升、无操作等待。记录数据源、episode、起止帧、置信度；边界不确定的段保留待复核。

阶段标签首先用于采样、动作目标筛选和分阶段评估。若希望网络显式预测阶段，需要另外定义可由在线观测推断的辅助任务，不能训练时输入人工真实阶段、推理时却没有该输入。

## 本轮 A/B 的具体过程

评估代码：`src/force_vla/pi05/hover_ab_evaluation.py`。

1. A 为 `outputs/pi05_force_tavla_aligned_30k_resume/checkpoint-030000`；B 为 `outputs/pi05_force_v3_resume_from_014000/checkpoint-030000`。
2. 两版都从自己的完整 checkpoint 恢复权重，并使用各自训练合同中的归一化统计；核对基础模型校验值。
3. 从 v3 验证集 episode 7、18、39 选择 Z 在 0.28–0.34 m 的窗口，按示范第 20 步的 Z 变化分成下压、Z 保持、回升，每条轨迹每类选 2 个；同组锚点至少相隔 60 帧。
4. 共选 18 个原始观测，每个包含相同的两路图像、文本、10D 状态和 2 秒 10 点关节力矩历史。每个模型分别使用相同的 32 组标准高斯初始噪声、10 次流匹配迭代，输出完整 50 步动作与力矩。
5. 共 18×32×2=1,152 次预测。所有输出均有限，两个模型的原始状态、参考动作、样本行和噪声种子逐项相同。
6. 保存选样图检查场景。episode 39/frame 185 是取料区，单独保留在全量结果中；治具统计按 X∈[0.17,0.23] m、Y∈[-0.48,-0.42] m 选择其余 17 个窗口。
7. 分别统计第 10、20、50 步的 Z 位移、方向类别、位置误差和同一观测下跨种子标准差。这里的“方向不一致”是固定观测的独立采样差异，不是真机连续运行中的方向切换率。

两版训练数据并不相同：A 使用原批次 91 条训练轨迹，B 使用新批次 28 条训练轨迹。B 的合同没有混入 A 的原 91 条。这不是“仅增加几条纠偏轨迹”的受控实验，不能由此断言是哪一种数据变化造成差异。两批数据位于不同目录；本轮没有对全部原始视频做跨目录重复检测。

## 实测结果

下表为治具区域 17 个窗口的第 20 步结果。下压组有 5 个观测，其余两组各 6 个观测；每个观测 32 个种子。下压/回升定义为相对当前状态超过 5 mm，Z 保持为 ±5 mm 内。

| 指标 | 旧模型 A | 新模型 B |
| --- | ---: | ---: |
| 应下压组：示范平均下压量 | 6.44 mm | 6.44 mm |
| 应下压组：预测平均下压量 | 8.67 mm | 3.28 mm |
| 应下压组：预测下压超过 5 mm | 78.75% | 26.88% |
| 应保持组：预测处于 ±5 mm 内 | 42.19% | 83.85% |
| 应回升组：预测回升超过 5 mm | 31.77% | 43.23% |
| 全部治具观测：平均跨种子 Z 标准差 | 4.51 mm | 3.55 mm |
| 全部治具观测：Z 平均绝对误差 | 8.66 mm | 5.47 mm |

第 50 步，在同一应下压组中，示范平均下压 13.20 mm，A 预测 11.45 mm，B 预测 6.58 mm。B 到块末端仍只有示范约一半的下压幅度，不能单凭增加执行步数就保证解决。

这些结果支持：

- B 在应下压观测上的下压幅度不足，大量预测被归到 Z 保持范围。
- B 同时更准确地保持，并减少了回升场景中的错误下压；不是所有能力都退化。
- A 有较强的向下偏好，不能因为更容易下放就认定其在接触阶段更安全或更准确。
- 本轮没有发现 B 整体随机波动变大。应下压组第 20 步的两版预测都没有出现超过 5 mm 的回升，主要差别是下压与小位移的比例。
- v3 总体误差更低，但关键下压能力不足，说明只用平均 loss 或平均位置误差选模型会遗漏这个问题。

这些结果不证明：

- 相似图像一定无法区分成功或失败；尚未进行视觉/力矩消融。
- 随机重规划是主要根因；本轮没有模拟接触动力学或闭环控制。
- 任何一个百分比等于真机成功率。这里只包含 3 条验证轨迹，32 个种子不是 32 个独立任务。
- 5 mm 分类阈值是安全边界。它仅用于描述预测，未修改机器人门控。

## 下一步优化解决什么问题

按顺序进行受控实验，每次只改变一项：

1. **恢复正常放置示范与纠偏示范的混合。** 目的：保留名义任务的下压行为，同时学习异常接触后的恢复。使用“数据源+episode”区分两批轨迹，避免重复 episode 编号导致划分错误。先固定验证轨迹，不把验证轨迹回流训练。
2. **补阶段标注并调整窗口采样。** 目的：提高正确对准、持续下压、就位动作的监督覆盖，减少操作员等待。对成功轨迹中的错误尝试，标出不应被模仿的动作目标；它们仍可作为纠偏窗口的历史观测。未来 50 步跨越坏动作区间时，需要逐步损失掩码或排除该目标窗口，不能只检查锚点标签。接触保持和成功压紧不能按低速度直接删除。
3. **重训后用同一清单重跑 A/B。** 同时看下压召回、错误下压、下压幅度、XY/旋转/夹爪误差，不能只提高下压幅度而损坏保持、释放和回升。
4. **单独评估加入外部关节力矩。** 目的：帮助区分接触后的卡住、压紧和纠偏。利用已有 31D 中的 `tau_ext_hat_filtered`，扩展归一化和历史编码后重新训练；对尚未接触时的对准判断仍需视觉和位姿。
5. **再评估视觉适配与动作块执行策略。** 视觉适配针对细微几何区分；动作块承诺/连续性约束针对重规划打断动作。当前结果不支持直接把随机重规划认定为主因，也不支持通过放大全部动作或放宽门控解决。

本轮 A/B 属于诊断，不会自动改变模型行为。上述训练与部署优化尚未执行。

## 结果和复现

结果目录：`outputs/hover_ab_20261012/`。

- `manifest.json`：checkpoint 路径、哈希、种子、样本帧、抽样规则和限制。
- `fixture_summary.json`：排除取料观测后的主结果。
- `summary.json`：全部 18 个观测结果。
- `per_window_summary.json`：逐观测的各步长统计。
- `*_records.jsonl`：逐模型、窗口、种子的位移摘要。
- `*_predictions.npz`：完整 50 步动作、预测力矩、原始状态、参考动作、种子和窗口行号。
- `fixture_vertical_predictions.png/.pdf`：治具区域曲线；阴影表示平均的观测内跨种子标准差，不是置信区间。
- `vertical_predictions.png/.pdf`：全部观测曲线。
- `selected_observations.jpg`：两路相机抽样图。
- `training_motion_audit.json`：训练分布补充核对。

完整评估需选择一个新的输出目录：

```bash
cd /data0/wx/force-VLA
bash scripts/run.sh --gpu python -u -m force_vla.pi05.hover_ab_evaluation \
  --output outputs/hover_ab_repeat \
  --seeds 32 --per-group 2 --inference-steps 10
```

仅重算已保存输出的统计与绘图，不加载权重、不使用 GPU：

```bash
cd /data0/wx/force-VLA
bash scripts/run.sh python -m force_vla.pi05.hover_ab_evaluation \
  --output outputs/hover_ab_20261012 --summarize-only
```

绘图通过 `hover_ab_plot.py` 使用系统已有 Matplotlib/NumPy；以 `/usr/bin/python3 -S` 隔离 `/usr/local` 包，只加载 `/usr/lib/python3/dist-packages`，没有安装或修改任何环境。首次采样的全部数值已成功保存；随后单独完成绘图依赖隔离并重算汇总，成功日志为 `outputs/hover_ab_20261012_summary.log`。

验证包括：分类边界、完美预测及相反随机模式的合成数值检查；两版输入一致性；输出形状、有限值和 1,152 条唯一采样记录；治具筛选；脚本语法及实际绘图输出。
