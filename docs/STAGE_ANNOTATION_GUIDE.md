# 关键帧与纠正阶段标注操作

> 2026-10-21：标注网页、草稿工具与旧审阅包已归档退役。下文保留为历史操作记录，网页路径和`prepare`命令不再可用；已确认标签、导入校验、索引构建和阶段训练仍保留。需要重新使用网页时，先按[恢复说明](../archives/stage_cleanup_20261021/README.md)恢复工具及资源。

原离线标注程序不连接机器人、不修改原始数据，不安装环境依赖。

## 三个概念

1. 之前 A/B 的曲线是模型输出反归一化后的物理坐标，没有经过真机门控和动作限幅。该实验中的下压不足不是安全限幅造成的。实机另有安全检查和控制跟踪，不能把两者混为一谈；导致模型幅度偏小的训练原因仍需受控实验确认。
2. 此处的“增加监督”是人工离线标注、筛选模仿目标后做 SFT 微调，不是立即开启人工在线纠正 RL。不会新增奖励、critic 或自动执行纠正动作。
3. A/B 复测首先读取录制观测离线推理，不启动机器人。真机短时闭环验证是之后独立的步骤。

## 第一步：先用 37、38 两条统一判断标准

页面分别为：

```text
outputs/stage_review_v3_train_20261013/episode-037/index.html
outputs/stage_review_v3_train_20261013/episode-038/index.html
```

1. 填写“标注人”，先按 0.5× 播放，整体了解何时接触、纠偏、下压和释放。
2. 两路视频同步显示，曲线依次为七维实测关节力矩、七维外部关节力矩、实测/目标 TCP Z。单位分别为 Nm、m。灰底只表示原 RB 区间。
3. 在关键位置暂停，用左右方向键或按钮逐帧看；Shift+方向键跳 10 帧。点击曲线、拖动滑条或输入帧号都能定位。
4. 曲线可切换整条轨迹、前后约5秒、前后约1.5秒。观察力矩变化时始终结合画面和位姿，不根据峰值自动判定失败。
5. 先记关键帧，再标连续区间。关键帧记录接触、开始纠偏、开始下压、确认就位和释放的边界；它们不会自动批准任何训练动作。

页面帧号从 0 开始，对应原始数据的 `frame_index`，不是处理后窗口的行号，也不是第几个训练 batch。视频按 30 Hz 编码；数值面板另显示实测时间，不能把名义视频时间当作没有抖动的机器人采样时间。

## 第二步：按阶段划区间，并判断动作是否值得模仿

区间采用 `[start_frame, end_frame)`：起点包含，终点不包含。例如某段最后一帧是 599，终点应填 600；下一段可从 600 开始。

- 定位第一帧，点击“起点设为当前帧”或按 `[`。
- 定位最后一帧，点击“终点设为当前帧+1”或按 `]`。
- 选择阶段、动作监督用途、判断把握，填写判断依据，点击“添加区间”。
- 发现边界不准，用表格的“编辑”；“移除标签”只移除浏览器标签，不删除视频或数据。
- 填写输入框时，快捷键不会接管文本输入；此时可以直接用按钮。

| 阶段 | 观察依据 | 动作监督用途建议 |
| --- | --- | --- |
| 接近/搬运 | 携带物料向目标移动，尚未接触 | 正确动作为“模仿” |
| 错误接触/卡住 | 画面显示顶边、偏斜、未入位；力矩变化仅作辅助 | 持续错误下压选“不模仿”；合理回退应拆到纠偏段 |
| 有效纠偏 | 回退、横移、旋转改善对准，或是明确合理的恢复动作 | 已确认的动作选“模仿” |
| 对准下压 | 有对准依据，物料沿正确位置持续进入配合 | “模仿”，不能只标开始一帧 |
| 就位/压紧保持 | 画面确认入位，进行必要压紧或保持 | “模仿”；低速度不能作为删除理由 |
| 释放/回升 | 放开物料并撤离 | “模仿” |
| 无操作等待 | 操作者停顿，且没有有效接触保持或调整用途 | “降采样候选”；彻底无效片段可“不模仿” |
| 不确定 | 看不清、证据矛盾或边界无法判定 | “待复核” |

阶段描述“发生什么”，用途描述“是否应让策略模仿这一段动作”。两者不能混用。例如错误接触状态可以是有效纠偏的起点，但制造错误的下压动作不一定值得模仿。

网页默认待复核，不能为了提高覆盖率把所有成功轨迹整段标成“模仿”。任一“不确定”阶段或把握必须保持“待复核”。备注建议记录“顶左边后回退”“旋转后可见入位”“只有力矩峰值，看不清接触”等可复核事实，不要推测成功原因。

可重复标多个纠偏区间，不受原 RB 只支持一段连续区间的限制。全部帧都覆盖后才能勾选“已检查并覆盖整条轨迹”；即使覆盖完整，仍可能包含待复核段，因此“完整”不等于可以全部训练。

## 第三步：导出并导入到 force-VLA

每条轨迹点击“导出标注 JSON”，例如得到：

```text
stage_episode-000037.json
stage_episode-000038.json
```

浏览器草稿保存在本机浏览器中，不等于已归档。换电脑、换浏览器或清理缓存前一定导出。可通过页面的“导入之前的标注 JSON”继续编辑。

把导出的文件复制到：

```text
/data0/wx/force-VLA/annotations/stage_inbox/
```

若下载就在这台机器的 `~/Downloads`：

```bash
mkdir -p /data0/wx/force-VLA/annotations/stage_inbox
cp ~/Downloads/stage_episode-000037.json ~/Downloads/stage_episode-000038.json \
  /data0/wx/force-VLA/annotations/stage_inbox/

cd /data0/wx/force-VLA
bash scripts/run.sh python -m force_vla.stage_annotations import \
  --files annotations/stage_inbox/stage_episode-000037.json \
          annotations/stage_inbox/stage_episode-000038.json
```

如果文件来自另一台电脑，先传到上述 inbox，再运行 import。程序不依赖 shell 当前激活的 Conda；`scripts/run.sh` 自动使用独立环境并隐藏机器人设备。

校验包括来源目录、原数据和视频哈希、训练合同、帧数、区间边界/重叠、关键帧范围、标注人和不确定段用途。通过后存到 `annotations/stages_v3/`，文件名包含数据源标识，避免不同批次相同 episode 编号相互覆盖。

改标后重新导入，若提示已有标签不同，使用 `--replace`：

```bash
bash scripts/run.sh python -m force_vla.stage_annotations import \
  --files annotations/stage_inbox/stage_episode-000037.json \
  --replace
```

旧版本先归档到 `annotations/stages_v3/history/`，再写入新版。相同内容重复导入不会产生多余历史文件。

## 第四步：生成可复核的窗口索引

```bash
cd /data0/wx/force-VLA
bash scripts/run.sh python -m force_vla.stage_annotations build-index \
  --annotations annotations/stages_v3 \
  --output outputs/stage_index_v3_round1

cat outputs/stage_index_v3_round1/summary.json
```

每次更新标签后使用新的输出目录，例如 `round2`，不会覆盖上次结果。

输出包含：

- `summary.json`：各轨迹标注覆盖、待复核量、各阶段可用窗口数量、标签哈希和原验证集。
- `window_review.parquet`：原窗口行号、阶段、未来50步逐步动作批准掩码和建议采样权重。
- `eligible_train_rows.json`：仅列出原训练集中未来50个动作都明确批准的窗口。

示例规则：锚点在有效纠偏段，过去2秒含错误接触，未来50步均为正确纠偏动作，可以保留；锚点虽正确，但未来50步有明显错误下压，则不会进入保守可用列表。原始帧没有删除或拼接。

未标注/待复核/不模仿目标一律不批准。降采样片段仍是已批准动作，但建议锚点采样权重为0.1；这是供下一轮实验审查的初始建议，不是已启用的训练规则。不能仅靠关键帧标记使窗口通过。

候选索引显式写 `training_ready: false`：普通训练不会自动读取这个侧文件、动作掩码或采样权重。不要把 `window_review.parquet` 当作训练窗口直接传入模型。2026-10-16已新增 `force_vla.pi05.stage_sampling`，可把已审定索引打包成训练入口消费的独立采样合同；具体指令见[阶段标注与外部力矩A/B实验](STAGE_EXTERNAL_TORQUE_AB_20261016.md)。该首轮实验使用当前28条中的一次成功和纠偏示范，尚未混合旧91条。

## 第五步及后续顺序

1. 先完成 37、38 两条，检查阶段边界与训练目标定义是否一致。
2. 按同一规则补标其余26条训练轨迹，尤其覆盖正确下压、就位、释放和接触保持，不仅标纠偏。
3. 审查窗口索引后，制定旧正常成功示范与新纠偏示范的混合比例，使用“数据源+episode”区分两批数据，并保留固定验证集。
4. 新建 SFT 微调运行；权重初始化、归一化、阶段采样和动作掩码需明确接入。不要直接普通 `--resume` 跨数据合同续训。
5. 用冻结的离线观测清单比较新旧模型，同时检查下压不足和错误下压、保持、回升。跨新训练合同复用固定 A/B 清单的入口需在接入训练时处理，不能假定当前 A/B 默认参数可直接兼容任意新合同。
6. 离线通过后，再单独安排真机短时测试。外部力矩输入、视觉解冻、动作块承诺分别做后续对照，避免同时改多项而无法判断作用。

本轮只完成标注与索引工具，没有代替操作者标注真实轨迹、启动新训练或部署。

已经生成的28条包可以直接使用，不必重复生成。需要新副本或先准备两条时：

```bash
cd /data0/wx/force-VLA
bash scripts/run.sh python -m force_vla.stage_annotations prepare \
  --episodes 37 38 \
  --output outputs/stage_review_pilot_new
```

要单独标注验证集用于评估，可显式指定 `--split validation` 和另一个输出目录；窗口索引生成器始终排除验证集。当前准备器支持本项目独立分轨迹、30Hz、H264、原视频从0秒起的数据格式，遇到共享视频偏移或帧数不一致会拒绝。

程序位置：

- `src/force_vla/stage_annotations.py`：准备、导入、校验、索引。
- `src/force_vla/stage_review_assets/`：离线网页、交互与曲线。

验证：Python单元及导入/归档/索引集成测试、Node标签校验与模拟DOM交互测试，以及28条轨迹的数值形状和56个视频的编码/帧数检查。没有可用的自动化桌面浏览器，未做真实浏览器逐帧播放验收；首次请确认两路画面和帧号对应后再正式标注。
